# Item use (server design)

Server-side rules for using items. The client contract is [Item use protocol](item-use-protocol.md).

## Item use

Right-clicking a Bag item uses it: gear is equipped into the slot it is worn in, any other item runs its item script. Right-clicking a worn item takes it off to the lowest free Bag slot. `docs/item-use-protocol.md` is the client contract.

- **Request and answer.** `CMSG_ITEM_USE` (`0x2082`, `CItemUsePacket`: `RequestId` 1, `Container` 2, `Slot` 3), accepted by `MapSessionFilter`, reaches `ItemUseHandler`, which hands it to `ItemUseService` (`Avalon.World/Items`, a DI singleton, tick thread only, no awaits). Each request gets **exactly one** `SMSG_ITEM_USE_RESULT` (`0x3091`, `SItemUseResultPacket`: `RequestId` echoed 1, `Result` 2, `CooldownMs` 3 only on `OnCooldown`, rounded up and at least 1, `Message` 4 only on `Refused`), to the requester only: at once for an equip or an instant use, when the cast ends for a cast-time use (its `SMSG_UNIT_START_CAST` is the acknowledgement meanwhile). A connection with no character gets nothing; an exception escaping the service is logged and answered `InternalError`. `ItemUseResult` is append-only from `Unknown = 0` (never sent): `Ok` 1, `NotFound` 2, `NotUsable` 3, `Dead` 4, `OnCooldown` 5, `AlreadyCasting` 6, `InCombat` 7 and `NotInCombat` 8 (reserved, nothing sends them), `WrongEquipSlot` 9, `LevelTooLow` 10, `WrongClass` 11, `TargetFull` 12, `Blocked` 13, `Interrupted` 14, `Refused` 15, `InternalError` 16.
- **Check order** (`ItemUseService.Begin`): dead (`Dead`, before anything else, so no hook, teleport or quest start runs for a dead user); the slot (a Bag or Equipment slot in range, not reserved, holding an item, else `NotFound`; any other container is `NotFound`); a worn item is taken off (below) and nothing else is asked, before any template lookup, so an item whose template a reload removed comes off too; the template (gone: `NotUsable`); gear is equipped and nothing else is asked; otherwise a `UseScript` (none: `NotUsable`), an ability cast in progress (`Spells.IsCasting`: `AlreadyCasting`), the item's and its group's cooldown (`OnCooldown`), the script resolved and built (missing or unbuildable: `InternalError`), the user's instance (`IItemUseHost`, else `InternalError`), then the script's `CanUse` (a line: `Refused` with it). A use that passed every check ends the item cast running (answered `Interrupted`), then runs `OnUse` at once or starts its cast bar. Using another item, gear included, interrupts a running item cast, but only once that use has passed its checks (owner decision): an equip or an unequip interrupts just before it moves anything, so the old use is answered `Interrupted` and the equip `Ok`, while a refused equip (`LevelTooLow`, `WrongClass`, ...), a refused unequip (`TargetFull`) or a refused script use leaves the cast running. The per-request Error logs (a missing or unbuildable script type, a hook that throws, a completion that throws) are written at most once per script and step per `ThrottledErrorLog.Interval` (10 s), counting the ones left out.
- **Equipping** (`ItemEquip`): an item whose template `Slot` maps to an equipment slot (`EquipmentSlots.SlotsFor`: both fingers for a ring, none for a gem or no slot) goes through `IInventoryService.TryMove` from its Bag slot, the drag's `InventoryMove` rules and marks, then `CharacterStatsRefresh.AfterGearChange`. An occupied slot swaps its item into the clicked Bag slot; a ring takes the first empty finger, else finger 1 (slot 7); a two-hander with an off-hand item worn is first checked for wearing (`InventoryMove.CanWear`, so a refusal moves nothing), then the off-hand item goes to the lowest free Bag slot (none: `TargetFull`; the clicked slot is not free), then the weapon (a failure after the off-hand moved is logged and not rolled back). Every check runs before anything moves (`InventoryMove.Decide` for a plain equip), and the running item cast is interrupted only then. Move answers map to use answers (`ItemEquip.Map`): `NotFound`/`InvalidSlot` to `NotFound`, `NotStackable` (a stack of gear) to `NotUsable`, `BankClosed`, `CannotDestroy` and `InvalidCount` to `InternalError`, the rest by name.
- **Unequipping** (`ItemEquip.Unequip`): a worn item goes to the lowest free Bag slot through `IInventoryService.TryMove` from its Equipment slot, the drag's `InventoryMove` rules and marks, then `CharacterStatsRefresh.AfterGearChange`. A full Bag answers `TargetFull` and moves nothing, the cast included. Taking an item off is always allowed: either hand (a two-hander or an off-hand item needs nothing special), in combat (only `Dead` refuses), and an item whose template is gone (the move rules read it as an item that stacks to 1). The move is decided (`InventoryMove.Decide`) before the running item cast is interrupted, and answers map as an equip's do (`ItemEquip.Map`). The lowest free slot is found with a plain loop over the Bag, so the request allocates no iterator.
- **Scripts.** `ItemScript` (`Avalon.World/Items`, World-side, never on `Avalon.World.Public`): `CanUse(ctx)` (null allows, a string refuses with that line; asked again when a cast completes), `OnUse(ctx)`, `OnCastStart(ctx)`, `OnInterrupted(ctx)`. `CanUse` is read only: effects belong in `OnUse`, a `Consume` made in `CanUse` is ignored, and every refusal belongs there, since an `OnUse` that returns without any effect still starts the cooldown. One instance per type, built through `QuestScriptServices` (loggers and `TimeProvider` only) and shared by every use, so it keeps no per-use state. Every hook is contained: a throw is logged at Error and answered `InternalError`, with nothing consumed and no cooldown; a throwing `OnCastStart` also ends the bar out loud (and is answered once: only when its own cancel ended the bar, not when the hook had already ended it), and a throwing `OnInterrupted` answers `InternalError` instead of `Interrupted`. Effects a hook applied before it threw stay applied. Scripts reach the world only through `IItemUseContext`.
- **The toolbox** (`IItemUseContext`, World-side, `ItemUseContext` built per hook call over the `ItemUseTools` singleton). Everything acts on the user, on units of the user's own instance, or on its party members in that instance, each change through the service that owns it, on the tick:
  - reads: name, level, class, health and power with their maximums, power type, position, map, `InTown`, `InCombat`, `InParty`, `ReturningToTown` (`RespawnInFlight`: a respawn, a party return, a scroll or a teleport under way), and the item's id, name, `UseValue`, stack count and configured cooldown.
  - `Consume(count)` marks part of the used stack spent (throws for 0 or past the stack); taken after `OnUse` returns. `HasBagRoom`/`GiveItem`/`TakeItem` go through `IInventoryService` (by template); `Money`, `GiveMoney` (false past `Game:MaxMoney`) and `TakeMoney` through `IWallet`.
  - `RestoreHealth` through `CombatService.RestoreHealth` (below); `RestorePower` through `CharacterEntity.GainPower` (capped, nothing for the dead or for a pool no cast spends).
  - `HostilesAround(radius)` lists living units of the instance hostile to the user (`Hostility.IsHostile`, so never the user, a party member or an unflagged player), nearest first; `Damage(target, amount)` is a raw hit on one of them through `CombatService.ApplyDamage(user, target, amount)`: dodge, crit, block and armour roll, the encounter forms, the creature gains threat, the user gets the kill's credit and loot. It answers true when the combat service took the hit (a dodge included); no self-damage, and a target the combat service ignores (an invulnerable creature, a corpse, a creature walking home, `CombatService.IgnoresHits`) or anything else answers false and does nothing.
  - `ReturnToTown()` starts `TownReturn` (`revive: false`, `dropEncounter: true`) to the town the current map's respawn resolves to; false in a town or while a move is under way. A reader who dies before arriving arrives in town revived, as a respawn would (owner decision). `Teleport(map, position?)` goes through `MapTeleport` and `World.TransferPlayer`: refused (false) for an unknown map, a level outside the map's band or a move under way; the instance is resolved as a portal resolves it (a town's shared one; in a party, the party's instance of a Normal map, re-checked on arrival as `EnterMapHandler` checks it: no longer in that party `MapNotFound`, full `InstanceFull`; otherwise the character's own); a given position is snapped to walkable ground with `IGroundNavigator.FindGround` inside the navigator's ground box (half-extents 2 m on X/Z and 4 m on Y, a 4 x 8 x 4 m box): X/Z kept with the mesh under it, the mesh's nearest point just beside it, kept as given on a map with no navmesh; no mesh in the box refuses the arrival with `MapTransitionResult.NoWalkableGround` (7), logged at Warning, nothing moved or saved; a destination instance whose build fails sends no `SMSG_MAP_TRANSITION` at all, as a portal entry or a respawn whose build fails does, and the item stays spent; with no position, the instance's entry spawn. A character that died while the instance built is not moved. The arrival drops the character from its encounter, sends the transition and the chunk layout (`MapArrival`), and saves the row's map, instance and position as a portal entry does (`ICharacterSaver.Save`). The item that started a move stays consumed whatever the arrival does (owner decision). While any move is under way (`RespawnInFlight`: a scroll return, an item teleport, a respawn or a party countdown return), `EnterMapHandler` refuses a portal entry with `MapTransitionResult.MoveInProgress` (8, owner decision), checked after the character and alive checks and before any lookup or build.
  - `CastAbility(id, free, point?)` through the cast system (`IItemUseHost.CastForItem`: `QueueAbility` for a cast time, `RunInstant` otherwise): an ability the user holds is cast as itself (its running cooldown refuses it, firing sets it); one it does not hold only from the catalog and only when instant; `free` skips the cost only; the global cooldown is neither checked nor started; refused while dead or while an ability is casting; a Cursor ability needs a finite `point`, toward which a Movement ability aims when given; an accepted cast marks the user in combat.
  - `GrantExperience` through `ExperienceAward.Grant` (the level cap applies). `StartQuest` through `QuestService.StartFromItem` (the accept's `QuestAvailability` rules, no giver, no conversation; `NotAvailable` for an unknown quest). `AdvanceQuest` through `QuestService.AdvanceFromItem`, for **Kill and Talk objectives only** of an Active quest's current stage, capped (`AddProgress`'s rules); Scripted objectives stay moved by the quest's own script, Collect by the Bag.
  - `SpawnCreature(template, distance, lifetime?)` through `ICreaturePlacementService.SpawnAt` (snapped to the ground as a procedural spawn is, #720, its AI script attached), 0 to 10 m in front of the user, never in a town, refused for a lifetime of 0 or less. `MapInstance` keeps each summon with the time it leaves (`IItemUseHost.DespawnAfter`, default 5 minutes, `ItemUseContext.DefaultSummonLifetime`, on the instance's `TimeProvider`) and on its tick drops a living summon whose time has come from its encounter and removes it (`RemoveCreature`), each summon contained on its own (a throw is logged at Error with the creature, and neither the tick nor the other summons pay for it); one killed first is the corpse removal's. An instance nobody is in does not tick, so its summons leave on its next occupied tick (owner decision). Loot, experience and quest credit are an ordinary creature's.
  - `PartyMembersHere()` lists the user's party members in the same instance by guid, the user excluded, alive or dead, at any distance; `RestoreHealthOf`/`RestorePowerOf` act only on a guid from that list (0 for anyone else), through `CombatService.RestoreHealth` (never the dead) and `GainPower`.
  - `ApplyAura(aura, member?)` puts a helpful aura on the user, or on a guid from `PartyMembersHere`, through the instance's `AuraSystem`, the user its caster (see Auras); false for a dead user, anyone else, or an aura not loaded, not helpful or refused.
  - `Tell(line)` sends the user a system line; `Whisper(from, text)` a line on `ChatChannel.Whisper` with that sender name, to the user only; `from` is not checked against any character.
- **Cooldowns.** `CharacterEntity.ItemCooldowns` (`ItemCooldowns`, World-side, never saved, so a logout resets them): per item template and per `UseCooldownGroup` (ordinal; blank is none), absolute times on the container's `TimeProvider`, nothing ticks them; the time left is the longer of the two. Started for `UseCooldownMs` once `OnUse` returns, whatever it consumed; a refusal, an interrupt or a throw starts none. Independent of the ability global cooldown.
- **The cast bar.** `ItemUseCasts` (one per `MapInstance`, reached as `IItemUseHost.ItemUses`, at most one cast per character), ticked by `MapInstance.Update` right after the ability cast system. Its cast ids come from the instance's ability cast ids (`IAbilityCastSystem.TakeCastId`), so an item's cast and an ability's never share one. `SMSG_UNIT_START_CAST` with `AbilityId` 0, `ItemTemplateId` (field 6), the cast id and the cast time in seconds, then `SMSG_UNIT_FINISH_CAST` or `SMSG_INTERRUPTED_CAST` with the same cast id and `ItemTemplateId` (field 4), to every connection within `Game:InterestRadius` of the caster (`EffectAudience`). It ends early, out loud, when the character moves (any change of position from where it began) or dies (checked each tick; damage alone never ends it), leaves the instance (`MapInstance.RemoveCharacter` interrupts it, contained), uses another item (gear included, and taking a worn item off) that passed its checks, or casts an ability `CastAbilityHandler` accepts (it interrupts after the cast system took the cast). At completion the same item instance must still be in the same Bag slot and the user alive (else `Interrupted`), and `CanUse` is asked again (a line: `Refused`). An interrupted use spends nothing and starts no cooldown. Every broadcast and callback is contained.
- **Consumption.** What `OnUse` marked with `Consume` is taken by instance id through `IInventoryService.TryRemove` after the hook returns, so it is saved and sent like any change (a removal that fails is logged at Error). A Town Portal Scroll is consumed once its return has started, though the move finishes later (owner decision).
- **Item heals.** `CombatService.RestoreHealth(healer, target, amount)` (World-side, not on `ICombatService`): a fixed amount, no stat scaling, no crit, never past the maximum and never lowering health above it (`HealRules.After`), never the dead; no heal threat and no encounter change; a heal that restored more than 0 is reported through `ICombatOutcomes.UnitHealed` and sent as `SMSG_UNIT_HEALED` with no ability id and `Result` None.
- **Data and the seeded items.** Nullable `ItemTemplate` columns `UseScript`, `UseCastTimeMs`, `UseCooldownMs`, `UseCooldownGroup`, `UseValue` (a whole percentage; `ItemUsePercent.Of` is `floor(maximum × UseValue / 100)`), migration `AddItemUse`, in the item schema and catalog (`useScript`, `useCastTimeMs`, `useCooldownMs`, `useCooldownGroup`, `useValue`) and editable through `PUT /world/{worldId}/item-template/{id}`, where a changed `useScript` must be a name in the world's published script catalog (`item`; an unchanged one, or a world that publishes no item list, is not checked), and a blank `useScript` or `useCooldownGroup` is stored as null (`TemplateFields`). `RestoreHealth` and `RestorePower` need `UseValue` set (the seed sets it): without it a potion restores nothing and is still spent. Seeded: Health Potion (1, `RestoreHealth`, 30) and Greater Health Potion (56, `RestoreHealth`, 60), refused at full health ("You are already at full health."); Mana Potion (2, `RestorePower`, 30, of Mana or Energy), refused for Fury and for no pool ("You cannot drink this.") and at full ("Your mana is already full." / "Your energy is already full."); the three share the `potion` group, 30 s. Town Portal Scroll (3, `TownPortalScroll`): a 3 s cast, then `ReturnToTown`, 30 s cooldown of its own, refused in a town ("You are already in town.") and while a move is under way ("You are already on your way to town."), usable in combat. Forest scrolls 9-11 have no script and answer `NotUsable`. `SeedIntegrityShould` pins them.
