# Live template editing

Editing item, ability, creature and aura templates on a running world through the REST API, and how the world applies them without a restart.

## Live template editing

Admins edit item, ability, creature and aura templates on a running world, and the world applies them without a restart.

- **Endpoints** (`[Authorize(Policy = AvalonRoles.Admin)]`, `[WorldScoped]`): `PUT /world/{worldId}/item-template/{id}`, `/ability-template/{id}`, `/creature-template/{id}` and `/aura-template/{id}`. The body is the read DTO minus `Id`, `Version` and `Editable`. The reads carry `version` (a lowercase hex SHA-256 of the row's stored values) and `editable`, and set `ETag: "<version>"`. An aura's modifier list replaces the stored one, merged by stat (updated, added, removed), and its version covers the modifiers; its `scriptName`, when changed, must be in the world's published script catalog (`aura`), and the aura must still fit every ability that applies it. An aura also carries its crowd control (#770): `control`, the flags as an integer mask (1 stun, 2 root, 4 silence, 0 none; the slow is derived from the modifiers, never a flag), which only a Harmful aura may set (else a 400 keyed `control`), and `breakOnDamagePct` and `breakPerSecondPct`, each a percentage from 0 to 100 (else a 400 keyed by its name). A creature template carries `stunDurationPct`, `rootDurationPct`, `silenceDurationPct` and `slowDurationPct`, each null (its rarity's) or a percentage from 0 to 100 (else a 400 keyed by its name); the rarity table they fall back to has no REST surface. These fields are in the version, so every aura's and creature's version changed once with #770. The ability template carries `auraId`: the aura must exist, pass the world's aura rules and fit what the ability affects (`AuraRules.LinkProblem`), else a 400 keyed `auraId`; a foreign-key violation that slips past (the aura deleted meanwhile) is a 400 too.
- **Editability is configuration, never code.** A world is editable only if its id is in `Application:Templates:EditableWorlds` (default empty; Helm `templates.editableWorlds`; the AppHost lists the local Development world). Anything else answers 403 `This world is not editable`, checked before the body is read. Production worlds stay out of the list. `Application:Templates:ReloadTimeout` (default `00:00:10`) bounds the wait for the world's answer.
- **If-Match and 409.** A `PUT` needs `If-Match: "<version>"`: missing gives 428, a stale one 409 `Changed since you opened it`. Other answers: 404 for an unknown id, 400 ValidationProblem keyed by camelCase field name. A `200` carries `{ template, reload: { status: "applied"|"failed"|"pending", summary } }`. The write is committed before the reload is requested, so `failed` and `pending` leave the saved row in place.
- **Reload over Redis.** After the commit the API publishes `{ requestId, areas }` on `world:{id}:reload` (`CacheKeys.WorldReloadChannel`); the world re-reads the areas (`Items`, `Abilities`, `Creatures`, `Auras`) through `IReferenceDataReloader`, the one `/reload` uses, and answers on `world:{id}:reload:result` (`CacheKeys.WorldReloadResultChannel`), matched by `requestId`. No answer within `ReloadTimeout` (world down, not yet subscribed: pub/sub is not queued) reports `pending`.
- **What players see.** A reload is forward-only, like `/reload`: new creature spawns use the edited template (live ones keep theirs), an aura already on a unit keeps the template it was applied with, abilities are read at character select (a held ability keeps its old metadata until the next select), and items are read from the templates afterwards.
- **Versions changed once with #1142.** Every item template's version changed once. `AllowedClasses` is now stored as class numbers (`smallint[]`) and no longer has a converter, so the version, which used to hash its comma-joined text, now hashes the list of class names. The versions of abilities 230-235 changed too, because their class's enum name changed from Healer to Cleric. An editor holding an older version gets a 409 and reads the row again.
- **An empty `allowedClasses` means every class, for items (#1171).** On a read and in a `PUT`, an item template's `allowedClasses: []` lets every class equip the item (the list limits equipping only, never a use); list classes only to restrict it to some (listing all four works but is not the intended form). Abilities keep their meaning: an empty list is a creature-only ability. The migration `ItemsAllowEveryClassWhenEmpty` emptied the lists of the 16 seeded items that named all four classes (ids 1-3, 9-11 and 56-65), so their versions changed once.
- **Damage types, resistances, ward and attribute requirements (#1178).** An ability template carries `damageType` (`Physical`, `Fire`, `Cold`, `Lightning`, `Blight`, or null): an Ally ability names none, a class ability that deals damage, directly or through a damaging aura, names one, and a creature-only ability may leave it null to deal its creature's type (`AbilityRules.Problem`, `AuraRules.DamageTypeProblem`); a refusal is a 400 keyed `damageType`. A creature template carries `damageType` (its basic attack's, and its null-typed abilities'), `fireResistance`, `coldResistance`, `lightningResistance` and `blightResistance`, each a percentage from -100 to 100 (negative takes more), and `evasionModifier` and `wardModifier`, each finite and 0 or more (0 is none); a value out of range is a 400 keyed by its name. An item template carries `requiredStrength`, `requiredAgility` and `requiredIntellect` (null for none), checked when the item is equipped. The public item and ability reads carry the same requirements and damage type, and a link preview says `Requires 12 Strength` or `Fire damage`.
- **Versions changed once with #1178.** The new columns joined the version, so every ability, creature and item template's version changed once; a creature's damage type is hashed under its property's name, `DamageType` (the column was `DmgSchool` until part B renamed it). An aura with a stat 5 modifier changed too, because the stat is now named `Evasion`, not `DodgePct`. An editor holding an older version gets a 409 and reads the row again.
- **The offence model (#1178, part B).** An ability template carries `tags` (names joined by commas, such as `"Attack, Melee, Area"`, or `"None"`: at most one of `Attack`, `Spell` and `Heal`, plus `Area`, `Projectile` and `Melee`; `DamageOverTime` is an aura's, never an ability's), `damageEffectiveness` (percent of the weapon's damage an Attack deals), `spellBaseMin`, `spellBaseMax` and `spellBasePerLevelPct` (a Spell's or a Heal's level-1 roll and its linear growth per level), `convertToType` and `convertPct` (the element an Attack converts part of its weapon's physical damage to, and how much, 0 to 100), and `addedType`, `addedMin` and `addedMax` (its own added damage). The ability rules decide what fits (`AbilityRules.Problem`, and `AuraRules.SourceProblem` for the aura it applies), and each refusal is a 400 keyed by the field it is about: `tags` for tags that do not fit what the ability affects, deals or is shaped as (or that its damaging or healing aura cannot scale with), `spellBaseMax` for a Spell or a Heal with nothing to roll, `damageEffectiveness`, `convertPct`, `convertToType`, `addedMax`, `addedType` and `spellBasePerLevelPct` for their own values, `damageType` for a class Attack that is not physical, and `cooldown` for a basic Attack whose cooldown is not 0 (its weapon paces it). An aura template carries `periodicEffectiveness`, the percent of its source's base roll added to `periodicBase` (finite and 0 or more, else a 400 keyed `periodicEffectiveness`). An item template carries `attackTimeMs`, the milliseconds between a weapon's basic attacks before attack speed, null for an item that is not a weapon and never 0 (a 400 keyed `attackTimeMs`); the public item read carries it too, and the public ability read carries the ability's offence fields. The retired `effectValue`, `scalingStat`, `scalingCoefficient` and `baseDamageCoefficient` are gone from the reads and the bodies.
- **Versions changed once with #1178, part B.** The new columns joined the version, and the retired ones left it, so every ability, aura and item template's version changed once. An editor holding an older version gets a 409 and reads the row again.
- **Bases and rarity (#1179).** An item template carries `baseKind` (the kind of base it is, such as `PlateChest`, `Sword` or `Ring`; null for a consumable or quest item) and `requiresAnyAttribute` (true when any one of its set attribute requirements is enough, as on a mace's Strength or Intellect; false when every set one is needed). Each refusal is a 400 keyed by its field: `rarity` for anything but `Common` or `Unique` (Magic and Rare are rolled on a copy, never a template's own; the table's `CK_ItemTemplates_Rarity`), `baseKind` for an unknown kind or a kind on an item with no `slot`, `maxStackSize` above 1 on an item with a `slot` (equipment never stacks), and `damageType1` or `damageType2` for a damage range without a type (a weapon's damage is always typed). The item power is gone from the reads and the bodies; a copy's item level is on the inventory read instead. The columns changed with the bases, so every item template's version changed once; an editor holding an older version gets a 409 and reads the row again.
- **Caveat: a release that changes a template in code overwrites the live edit.** The templates are seeded from `WorldDbContext`, so a migration that changes that seed rewrites the row, edit included. Re-apply the edit after such a release.
