# World maintenance

Scheduled maintenance cutoffs, the derived world status, admission checks at every door, and the restart drain. Operator settings are in the [Configuration reference](configuration-reference.md); the client view is in [Character login flow](character-login-flow.md).

## World maintenance

An operator schedules a maintenance cutoff for one world, the world counts down, and at the deadline every non-Admin session is closed while Admins stay to verify the world. `docs/configuration-reference.md` (World Maintenance and Readiness) and `docs/character-login-flow.md` (Maintenance Admission) are the operator and client views.

- **State** lives on the auth `Worlds` row (`MaintenanceEnabled`, `MaintenanceRevision`, `MaintenanceDeadlineUtc`, migrations `AddWorldMaintenance` and `RemoveStoredWorldStatus`; the stored `Status` column is gone). `WorldMaintenanceRepository.TransitionAsync` writes the three columns by compare-and-set on the revision, so the last committed transition wins and the revision orders them; a repeated `on` (or `off`) changes nothing and keeps the first deadline. `WorldMaintenanceControl.SetAsync` (Infrastructure, shared by the API and the command) commits, logs the actor, then publishes the revision on `world:{id}:maintenance`, best-effort; a request that changed nothing (the revision did not move) is neither logged as a transition nor published. World metadata updates write by column too (`WorldRepository.UpdateMetadataAsync`), never touching the maintenance columns.
- **Status is derived** (`WorldReadiness.Resolve`): an enabled row whose deadline has passed is `Maintenance`, otherwise a fresh `world:{id}:ready` heartbeat is `Online` and none is `Offline`. A world counting down stays `Online`. Create and general update requests cannot set it.
- **Controls:** `GET`/`POST`/`DELETE /world/{id}/maintenance` (Admin policy; `graceMinutes` 1-60, default 5), and `/maintenance on [minutes]|off|status` in the world (`MaintenanceCommand`), which requires the `AccountAccessLevel.Admin` flag itself (a mask test, so `Console` is refused). The command never awaits: its read and transition run off the tick through `ctx.Then`, and the callback applies the committed state at once.
- **The world side keeps to the tick rules (#639).** `WorldMaintenanceCoordinator` (`Avalon.World/Maintenance`) holds the applied state. `InitializeAsync` reads the row after `World.LoadAsync` and before the tick and the listener start (#665), and a missing row fails the start. The Redis notification (`WorldServer.MaintenanceNotice`) and `WorldMaintenanceReconciler` (every 5 s, for a missed notification) read the row off the tick and only `Offer` it, keeping the newest revision; `Advance`, called by `WorldServer.Update` before the session pass and contained there, applies the newest offered revision, sends the countdown on `SChatMessagePacket.System` (at the start, 3 min, 1 min, 30 s and each second from 10 to 0, driven by the stored deadline; a late tick skips stale thresholds; a restart replays no start line), and at zero blocks and closes every authenticated non-Admin connection with `DisconnectReason.Maintenance` (6) through the usual close, despawn and save. `Advance`, `ApplyCommitted` and `RunIfEntryAllowed` assert `TickThreadGuard`. Blocking goes through the World-side `IMaintenanceBlockable` (not on `IWorldConnection`, so no mod can silence a player): `WorldConnection` then drops every queued and new packet.
- **Admission is checked at every door**, each with the actual Admin flag: the REST game admission, at the join ticket's issue and again at its redemption by the world server (`GameServerAllocator`, which reads the row: a non-Admin at or past the deadline is neither offered the world by `POST /game/worlds` nor issued a ticket for it, `WorldUnavailable`, and a world with no heartbeat is offered to nobody; the admitted session's identity and access level are published on the connection once, from the API's answer, `WorldConnection.PublishAdmission`), each character select (`IWorldEntryGate.CheckAsync` off the tick through `CheckOffTick`, the one helper the select and the readiness barrier share, the account id read on the tick, answered by a continuation; a refusal closes with `Maintenance`, before anything is read), and the final spawn (`CharacterReadinessBarrier.RequestRelease`, a fresh gate check and then `RunIfEntryAllowed` on the tick, against the state this world has applied). A gate decision lasts 5 s and, for a non-Admin, never past the deadline. A failed read refuses a new entry: the admission answers `ServiceUnavailable` and closes, and a character select or the final spawn closes that connection with `Maintenance`. `CheckOffTick` never faults: a check the database work queue refuses because it is saturated, one that throws and one that takes more than 5 s are each a refusal (#821), so the select or spawn waiting on it is always answered; the select runs its check on its own work queue. Every failure is logged at Error by exception type only, at most once per 10 s with the count left out (the gate's own read failures likewise). It never closes a session already in game.
- **A stop drains first (#768).** `WorldServer.OnStoppingAsync` (the listener already stopped) calls `WorldMaintenanceCoordinator.DrainForRestartAsync` before it stops the tick: a restart countdown held in memory only, beside the persisted state and never in it (no row write, no Redis publish, no revision, so neither a notification nor the reconciliation can replace it, and the next pod does not start in maintenance). `Advance` runs it on the tick after the persisted countdown, on the same schedule with its own lines ("The world restarts for an update in 5 minutes." ... "Restarting now."); it ends at its deadline, blocking non-Admin packets and entry, or as soon as no authenticated non-Admin connection is left; the unchanged stop then closes everyone with `ServerShutdown` and saves. `World:Shutdown:DrainTime` (0 = no drain, the shipped default) and `SaveMargin` (`WorldShutdownConfiguration`, required, validated) set the world host's `HostOptions.ShutdownTimeout` to their sum (`AddWorldShutdown`, the world host only); Helm `shutdown.drainSeconds`/`saveMarginSeconds` render them and `terminationGracePeriodSeconds` = drain + margin + 15. The realm list shows the world `Offline` during the drain, as before: the ready heartbeat stops with the host. `SaveMargin` is at least `WorldShutdownConfiguration.MinimumSaveMargin` (the 20 s save wait plus the 1 s drain backstop; Helm refuses under 21).
- **An admission in flight at SIGTERM does not hold the drain:** `CallListener` drops every packet once the server is stopping, and an admitting connection has no character yet, so nothing is lost.
