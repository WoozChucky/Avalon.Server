# Auras (server design)

Server-side rules for auras. The client contract is [Aura protocol](aura-protocol.md).

## Auras

Auras: timed effects on a character or a creature, periodic damage or healing, stat modifiers (buffs, debuffs, slows), or both, put on by abilities, item scripts and aura scripts. No crowd control and no dispel yet. `docs/aura-protocol.md` is the client contract.

- **Data** (World DB reference data and balance tables, migrations `AddAuras` and `SeedAuraContent`): `AuraTemplates` (`Id`, `Name`, `Icon`, `Kind` Helpful 1 / Harmful 2, `DurationMs` above 0, `TickIntervalMs` at most the duration and 0 for an aura that never ticks, `PeriodicKind` None 0 / Damage 1 / Heal 2, `PeriodicBase`, `ScalingStat`, `ScalingCoefficient`, `BaseDamageCoefficient`, `Stacking` Refresh 1 / Stack 2 / Independent 3, `MaxStacks`, nullable `ScriptName`) and `AuraStatModifiers` (keyed `(AuraId, Stat)`, cascading from the aura; `Stat` Armor 1, AttackDamage 2, AbilityDamage 3, CritPct 4, DodgePct 5, BlockPct 6, HastePct 7, MovementSpeed 8, MaxHealth 9, MaxPower 10; `Kind` Flat 1 / Percent 2; `Value`). The domain enums start at 1, so a missing value is refused rather than read as Helpful or Refresh (`AuraPeriodicKind.None` is 0). Check constraints hold the database to the rules: `CK_AuraTemplates_Kind`, `_PeriodicKind`, `_Stacking`, `_ScalingStat`, `_DurationMs`, `_TickIntervalMs` (at most the duration, above 0 for a periodic aura), `_MaxStacks` (1 or more), `_PeriodicBase`, `_ScalingCoefficient` and `_BaseDamageCoefficient` (finite, 0 or more), `_PeriodicFitsKind` (a harmful aura never heals, a helpful one never damages); `CK_AuraStatModifiers_Stat`, `_Kind`, `_Value` (finite, above -1,000,000, and a percentage above -100). `AbilityTemplate.AuraId` (nullable; foreign key `FK_AbilityTemplates_AuraTemplates_AuraId`, `Restrict`) names the aura every unit the ability's shape affects receives from the caster; the world reads it from the live ability catalog at apply time, never from `AbilityMetadata` (World.Public). An ability's direct amount is gated on its `Effects`: a Hostile ability hits only when `Effects` has `Damage`, an Ally one heals only with `Heal` (`AbilityRules.HasDirectEffect`), so an aura-only ability deals nothing directly and advertises `AbilityAmountKind.None`; `AbilityRules.Problem` refuses an ability with neither a direct amount nor an aura ("the ability does nothing").
- **Catalog.** `AuraCatalog` (`Avalon.World/Auras`; the Auras reload area, `StaticData.Auras`, empty before the first load) loads every row `AuraRules.Problem` accepts and whose `ScriptName`, when set, is a loaded `AuraScript`, and refuses the rest with an Error naming each: an unknown enum, a duration of 0, a periodic aura with no interval, an interval longer than the duration, `MaxStacks` below 1, a negative or non-finite amount, a harmful aura that heals or a helpful one that damages, an unknown stat or modifier kind, a non-finite modifier, a percentage at or below -100, a stat modified twice. The Abilities reload area checks its links against an aura catalog of its own read, built silently, so each aura refusal is logged once, by the Auras area. `AuraRules.LinkProblem` (the world's `AbilityCatalog`, the API and the simulator all call it) refuses an ability naming an aura that is missing or refused, or one that does not fit what it affects: a Hostile ability applies only a harmful aura, an Ally one only a helpful aura (`AuraRules.Fits`).
- **The rules in `Avalon.Combat`**, shared with the balance simulator: `AuraRules` (`Problem`, `LinkProblem`, `Fits`, `TickCount`, `Snapshot`, `TakeTick`, `NextStacks`, `KeysByCaster`), `AuraSchedule`, `AuraSnapshot`, `AuraStats`, `AuraStatTotals`, and `HitResolver.ResolvePeriodic`/`ResolvePeriodicHeal`. **The schedule is anchored at expiry:** `n = max(1, floor(DurationMs / TickIntervalMs))` ticks (none with no interval) at `ExpiresAt - j x Interval`, j from n-1 down to 0, so the last lands at expiry; `Due(now)` owes every tick whose time has come, never more than are left. **The snapshot**, taken once at apply from the caster (`HitResolver.AbilityBase`): `PeriodicBase + ScalingCoefficient x the caster's stat + BaseDamageCoefficient x one roll of its base damage` (a creature's natural `DamageMin..DamageMax`, a character's main hand, none without a weapon; drawn through the combat service's `ICombatRandom` only when the coefficient and the range are above 0), divided by n, kept with the caster's crit chance and level. A tick deals the per-tick amount times the stacks, rolls crit with that chance (the one draw) and, for damage, meets the target's armour against that level; never a dodge or a block. **The fraction carry:** each tick's unfloored amount goes into the aura's own `PeriodicCarry` and only whole points are dealt or healed (`AuraRules.TakeTick`, as regeneration takes them, no minimum of 1); the last tick rounds what is left, a half up, so the ticks add up to the total; a refresh starts the carry over. **Stacking:** Refresh renews the duration, schedule and snapshot (a fresh roll); Stack adds one up to `MaxStacks` and renews the same way; Independent keeps one copy per caster, each renewed by its own caster only. **The fold** (`AuraStats`): each stat becomes `(base + flat) x max(0, 1 + percent / 100)`, every modifier times the stacks held, a whole-number stat rounded and never below 0 (maximum health never below 1); the caps apply afterwards, where they already did. `MovementSpeed` and `HastePct` are percentage points: a Flat modifier adds points (Crippled's -30 is a 30 % slow), a Percent one scales the points the unit already has.
- **Holders.** `UnitAuras` (`Avalon.World/Auras`) is `CharacterEntity.Auras` and `Creature.Auras`, World-side, never on `ICharacter`, `ICreature` or World.Public, so no mod can add, end or read auras; any other `IUnit` holds none (`AuraHolders`). Each held copy is an `ActiveAura`: the template it was applied with (kept, so a reload never changes it), caster guid, source ability (`AuraSource`: its threat multiplier, heal threat and power gain), stacks, snapshot, schedule and carry, with a key unique among its unit's auras, from 1, the client's handle. A unit holds at most `Game:MaxAurasPerUnit` (default 32, range 1-256); past it a new aura is refused and logged, while a copy already held still refreshes or stacks.
- **`AuraSystem`** (one per `MapInstance`, `MapInstance.Auras`, reached through the World-side `IAuraHost`; tick thread only). **Apply** (`Apply(caster, target, aura, source)`): who may receive it is the caller's to decide (the ability's shape and `Hostility`, an item's party rule). It refuses an aura no longer loaded, one that no longer fits the ability applying it (a reload of either side), a dead target, a harmful aura on a target every hit passes over (invulnerable, a corpse, a creature walking home) and a new aura past the cap, each refusal logged at most once per aura per 10 s; otherwise it takes the snapshot, places the copy, refreshes the stats it modifies and runs the script's `OnApply` or `OnStack`. A harmful aura from a caster enters combat through `CombatService.EnterAuraCombat`, as a dodge does: the encounter forms (the caster at the initial threat seed), a creature is told `OnAttacked`, both sides are tagged in combat; further threat comes only from ticks. **The pass** (`Update`) runs right after the ability cast system and before the item cast bars, the combat service and the creature scripts, on the instance's `TimeProvider`, on absolute times, so a late pass catches up every owed tick, aura by aura in the order applied. For each unit holding an aura: a dead one loses them all; a creature walking home loses its harmful ones (reason `Reset`, owner decision); then each aura expires if its template is no longer loaded (reason `Expired`), takes its owed ticks, ends if its script asked, and expires once its time is up, after its last tick. A tick that kills its unit ends every aura it holds. The caster is credited (threat, power gain, the kill) only while it is alive in that instance (`CasterHere`); otherwise the aura ticks on its snapshot from nobody, and a killing tick is `CreatureKilled(creature, null)`: nobody is eligible, so no experience or quest credit, and every table drop is free for all at once. **The empty-instance skip** (owner decision): an instance with no players runs no aura pass, and the first tick with players (or an arrival, before it joins) calls `SkipOwed`, which ends every aura whose end has passed and leaves the rest owing only the ticks at or after now, so nothing bursts on re-entry. **Death** ends every aura through `ICombatOutcomes.UnitDied`, which every death in `CombatService` reports, with the pass as a safety net. **Containment:** a tick that throws is logged (throttled per aura) and keeps its carry; anything else in a unit's pass is logged (throttled per unit) and the pass goes on; `MapInstance` contains the pass, an ability's application and the death removal, each with its own `ThrottledErrorLog`.
- **Ticks** go through two World-side `CombatService` methods. `ApplyPeriodicDamage`: a target every hit passes over, or a dead character, takes nothing and draws nothing. With a character caster present the encounter forms, a creature gains threat (the dealt amount x the source ability's `ThreatMultiplier` x the class modifier) and hears `OnAttacked`, the caster gains the source ability's `PowerGainPerHit` per tick that damaged a living unit, and both are tagged in combat; a tick between two players restarts their PvP timers as a hit does, except in a town. A creature caster's tick counts only in the encounter its target is already in and never forms or rejoins one (the aura formed it when it landed), so a creature that gave up the fight and reset at home stays out of it, ticks or not. A creature's health is changed directly, and written only by a tick that dealt something (no `OnHit`, so its script broadcasts nothing), a character's through `OnPeriodicHit`, with Fury from damage taken; a god-mode character takes 0. `ApplyPeriodicHeal`: never the dead, never past the maximum (`HealRules.After`), heal threat by the source ability's `HealThreatPerHp` for the health actually restored. A damage tick of at least a whole point, or a heal tick that restored health, is reported through `ICombatOutcomes.PeriodicTick`, which sends the existing damage and heal packets with `AuraId` and no `AbilityId` to whoever hears a hit or a heal there (#532); a 0-point tick sends nothing but still counts as combat.
- **Abilities** apply theirs in `AbilityEffect.Apply`, after the direct amount: a Hostile ability with `Damage` hits first, and only a hit that landed (`HitOutcome.Landed`) applies the aura, so a dodged or ignored hit applies none, while an aura-only cast is never dodged; an Ally ability heals first when it has `Heal`, then applies its aura to every ally its circle covers, the caster included. `IAbilityArena.ApplyAbilityAura` reads the ability's live row, so an `AuraId` whose aura a reload dropped applies nothing (logged, throttled).
- **Stats.** A character folds its auras through `CharacterStatsCalculator.Calculate(..., character.Auras.StatTotals)` at every refresh, after gear, so select, gear, level-up and auras agree; an applied, stacked or removed aura with modifiers refreshes at once with `KeepShare` (`AuraStatsRefresh`), the saved `CharacterStats` row included, and the sheet, movement speed and ability amounts reach the client through their usual flushers. A creature folds `Creature.AuraTotals` into `Combat` (attack, ability damage, crit), `Defence` (armour, dodge, block), its haste (from 0) and its maximum health (on top of the party scaling, keeping its share); its slow is `Creature.SpeedFactor` (`1 + aura movement points / 100`, the points within the floor and cap it spawned with), read by both locomotions through `CreatureSpeed.Of`, so scripts keep writing `Speed` from their template.
- **Scripts.** `AuraScript` (`Avalon.World/Auras`, World-side, never on World.Public) is named by `AuraTemplate.ScriptName`, found by type name once, at `Load()` (never hot-reloaded), and built once per type through `QuestScriptServices` (`AuraScripts`, a DI singleton); one instance serves every aura that names it, so it keeps no per-aura state. Hooks: `OnApply` (a new copy), `OnTick` (after the tick's amount), `OnStack`, `OnRemove(ctx, reason)` (`AuraRemoveReason`: `Expired` 1, `Death` 2, `Cancelled` 3, `Script` 4, `Reset` 5). Each is contained: a throw is logged at most once per aura and hook per 10 s, and the aura goes on. `IAuraContext` gives the aura's reads (id, name, the target and its health, the caster, `CasterPresent`, stacks, time left, duration) and four acts that go through the owning services and work only while the hook runs: `Remove()` (reason `Script`, once the hook returns), `Damage(amount)` (a tick-like hit, crit and armour from the snapshot, the caster credited while present), `Heal(amount)` (a fixed heal) and `Tell(line)`. Aura scripts are trusted (owner decision): `Damage` does no hostility check, from any aura, a helpful one included. A first hook that kills its target ends every aura on it, and the corpse enters no combat. No aura script is shipped or seeded yet.
- **Saving.** `CharacterAuras` (Character DB, migration `AddCharacterAuras`, key `(CharacterId, Slot)`, cascading from `Characters`; `CK_CharacterAuras_Stacks` 1 or more, `CK_CharacterAuras_TicksLeft` 0 or more): aura id, caster guid, source ability, stacks, time left, duration, ticks owed, the snapshot (per tick and stack, crit, caster level), the carried fraction and when it was applied. Every change marks `SaveStateTracker.AurasChanged`, and every save of a character holding an aura, or marked by a change, carries a `CharacterAuraWrite` (built in `CharacterSaveSnapshot`) that deletes all its rows and inserts the current ones, the time left read on `CharacterEntity.Clock`; a dead character saves none. Only a character caster is saved: any other guid is numbered per run, so it is saved as nobody. Select restores them with `AuraRestore`, one more `CharacterSelectHandler.Step` and the last before the pending spawn, contained (a failure costs the auras, never the select): each under the template loaded now (a missing one dropped with a warning), at most `MaxAurasPerUnit` (the earliest applied kept; any row dropped marks the auras changed, so the next save deletes it), stacks capped at the template's `MaxStacks`, the carry restored, and one overdue tick kept (`AuraSchedule.Restore`: a save taken after a tick came due and before the pass took it still owes that tick). Their time stands still while the character is offline and is **held until spawn** (`UnitAuras.HeldSince`): `MapInstance.AddCharacter` resumes it (`ResumeHeld`), so the loading screen costs nothing, and a save taken meanwhile reads the time left at the hold. **Aura time also pauses while a character moves between instances** (portal, scroll, respawn, party return): `World.TransferPlayer` holds its auras at the removal (`UnitAuras.Hold`, unless already held) and the target's `AddCharacter` resumes them, shifted by the time between, so no tick is lost and none is paid in a burst (the move is synchronous today, so the shift is about 0). A logout or despawn holds nothing. Creatures never save.
- **Replication**, in each instance's state broadcast after `SMSG_WORLD_STATE_ADD`: `SMSG_AURA_LIST` (0x310E: `UnitGuid` 1, `Entries` 2) for every unit newly in a client's view that holds an aura, and always for the client's own character when it is (re)added, empty too, so every entry and transfer replaces what the client held; `SMSG_AURA_UPDATE` (0x310D, the same fields), at most one per unit per tick with that tick's changes in order, to the unit and every client that has it in view (`CharacterCharacterGameState.Knows`), skipped for a unit listed that tick; every unit's changes are cleared once the broadcast is done, seen or not, and also when it throws. `AuraEntryDto`: `AuraId` 1, `InstanceKey` 2, `CasterGuid` 3, `Stacks` 4, `RemainingMs` 5 (rounded up), `DurationMs` 6, `Action` 7 (`AuraUpdateAction`: `Applied` 1, `Refreshed` 2, `Stacked` 3, `Removed` 4; absent in a list). Tick packets carry `AuraId` in `SUnitDamagePacket` field 6, `SCharacterDamagePacket` field 7 and `SUnitHealedPacket` field 7.
- **The cancel.** `CMSG_AURA_CANCEL` (0x2104: `AuraId` 1, optional `InstanceKey` 2), with a `MapSessionFilter` entry, reaches `AuraCancelHandler`, which ends the sender's own helpful auras through its instance's `AuraSystem.Cancel`, checked in the order `Dead`, `NotFound` (no copy of the aura, or none with that key, matched as given), `NotCancellable` (harmful), then `Ok`: with a key only that copy ends, without one every copy of the aura (owner decision), reason `Cancelled`. Exactly one `SMSG_AURA_CANCEL_RESULT` (0x310F: `AuraId` 1, `Result` 2; `AuraCancelResult` `Ok` 1, `NotFound` 2, `NotCancellable` 3, `Dead` 4, `Unknown` 0 never sent), sent at once, so ahead of that tick's `SMSG_AURA_UPDATE`; a throw is logged and answered `NotFound`; a connection with no character gets nothing.
- **Items.** `IItemUseContext.ApplyAura(aura, member?)` puts a **helpful** aura on the user, or on one of `PartyMembersHere`, with the user as caster and no source ability; false, doing nothing, for a dead user, anyone else, an aura not loaded or not helpful, or one the aura system refused; contained (`ItemUseTools.AuraFailures`).
- **The REST API.** `GET /world/{worldId}/aura-template` (paged, page size at most 50) and `/{id}` (`AuraTemplateController`, `[WorldScoped]`, Player policy) return `AuraTemplateDto` with its modifiers, `version` and `editable`; `PUT /world/{worldId}/aura-template/{id}` edits it live (see Live template editing). `AbilityTemplateDto` and its edit carry `auraId`. A character's saved auras are `GET /world/{worldId}/character/{id}/auras` (`CharacterAurasDto`, by slot, each caster as `casterCharacterId`, a character id of that world or null for nobody; the owner or a game master, as the other character sub-resources; 404 for an unknown character), as the world last saved them (`ICharacterAuraRepository`, a required dependency). The world publishes its aura script names in its script catalog (`aura`).
- **The exporters.** `tools/Avalon.Exporter -- aura-catalog` writes `schema/auras/aura-catalog-v1.json` (id, name, icon, kind, duration, tick interval, periodic kind, stacking, `maxStacks` and modifiers, enumerations as numbers listed in its `$comment`; no amounts), pinned against the seed by `AuraCatalogExportShould`; `ability-catalog` carries each ability's `auraId`. Both need a World database.
- **The balance simulator** reads `AuraTemplates` and `AuraStatModifiers` from the seed, takes overrides keyed `Aura.<id>` and `AuraStatModifier.<auraId>.<Stat>`, and models damage and healing over time and stat auras through the same `Avalon.Combat` rules (snapshot, schedule, carry, fold, `ResolvePeriodic`); movement modifiers change nothing there (nobody moves), the cap is never reached, no aura script runs and nothing stalls. `SimulatorParityShould` pins the aura cases against the server.
- **The seeded content** (`SeedIntegrityShould` pins it).
