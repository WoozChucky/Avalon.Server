# Chat and commands

Chat commands (how to add one, access levels, failure reporting), chat channels, whispers, the chat rate limit and the ignore list.

## Chat Commands

Commands live in `Avalon.World/Chat/` (the party commands in `Avalon.World/Parties/PartyCommands.cs`, the ignore commands in `Avalon.World/Social`). To add a new command:
1. Implement `ICommand`: `Name`, `Aliases[]`, optionally `RequiredAccess`, and `void Execute(CommandContext ctx, string[] args)`.
2. Register as `services.AddSingleton<ICommand, YourCommand>()` in `ServiceExtensions.AddWorldServices`.
3. `CommandDispatcher` resolves all `ICommand` registrations from DI automatically (name and aliases, case-insensitive).

**A command runs on the tick, to completion, and never awaits.** `ChatMessageHandler` calls `ICommandDispatcher.Dispatch(connection, packet)` synchronously on the tick for every `/`-prefixed message, with no continuation around it; `Dispatch` returns false for an unknown command or one the caller may not run, and the handler then answers "Unknown command.". `Execute` returns `void`, so `await` does not compile in it. `ctx.Reply(text)` sends the caller a system line. Work that cannot finish on the tick goes through `ctx.Then(task, callback)` (and `Then(Task, Action)`): the task is handed, settled so it never faults, to `IWorldConnection.EnqueueContinuation`, and the callback runs on a later tick, only once the task has succeeded. `/reload` and `/ignore` (for an offline name, #723) use it; `/godmode`, `/pvp`, `/w`, `/unignore`, `/ignorelist` and the party commands are plain synchronous. `CommandsNeverBlockTheTickShould` scans every `ICommand` in `Avalon.World` by reflection, nested types included (so lambdas and closures), and fails one with an async method or a call to `Task.Result`, `Task.Wait` or `GetAwaiter().GetResult()` (`TickBlockingScan`); it does not follow calls into other types or look for other blocking calls such as `Thread.Sleep`, so those stay the author's to avoid.

`ICommand.RequiredAccess` defaults to `AccessLevels.Player`, so a command that declares nothing stays runnable by any logged-in player — `Tournament` and `PTR` included: they are players with exactly the Player permission set, differing only in which worlds they may enter, and the API's Player policy lists them too; `ReloadCommand` is the one exception so far, declaring `AccessLevels.GameMaster`. `CommandDispatcher` checks `RequiredAccess.Allows(connection.AccessLevel)` — a mask test, not an ordinal one, because `AccountAccessLevel` is `[Flags]` and `Tournament`/`PTR` are not above `Admin`, so a `>=` comparison would let either through a `GameMaster` gate. A caller without access gets exactly "Unknown command.", the same as a caller who typed a command that doesn't exist — the dispatcher never reveals which commands are staff-only. `IWorldConnection.AccessLevel` has no setter: `Avalon.World.Public` is the future modding API, and a settable access level there would let a mod promote any player to GM. The server assigns it through `IAccessLevelAssignable` in `Avalon.World`, twice: at the world key exchange (`ExchangeWorldKeyHandler`, before it publishes `AccountId`, so the maintenance cutoff can tell an Admin waiting at character selection and leave it connected), and again at character select from a fresh account read. Do not drop the exchange assignment: without it every Admin still at character selection is closed at the maintenance deadline.

**Every failure is reported one way, synchronous or not.** A command that throws, a task handed to `ctx.Then` that faults or is cancelled, and a `Then` callback that throws all reach `CommandDispatcher.ReportFailure`: logged at Error with the command and account, and told only to a caller holding the `GameMaster` or `Admin` flag, as `Command /<name> failed: <ExceptionType>.` (the type name only, the message and stack stay in the log; a cancelled task reports `TaskCanceledException`, a task with several exceptions `AggregateException`). Everyone else, `Console` included, gets silence, because an error line would reveal that the command exists and what broke inside it. A command that throws still counts as dispatched, so nobody gets "Unknown command." for it.

**Chat channels.** `SChatMessagePacket.Channel` (field 6, `ChatChannel`: `Say` 0, `Party` 1, `System` 2, `Whisper` 3). A message without a `/` is said: `ChatMessageHandler` sends it on `Say` to every connection in the sender's `MapInstance`, the sender included (only to the sender when its instance cannot be found). There is no world-wide chat. `/p` goes to the sender's party on `Party` (see Parties). **Sender's class (#763):** `SChatMessagePacket.CharacterClass` (field 8, `ushort`, the `CharacterClass` value, as the party roster sends it) is the sending character's class on said, party and whispered lines, the whisper's echo included (both copies name the sender in `CharacterName`; the recipient's class is not sent), so a client can colour the name; it is 0 on System lines and on a script's line (`ItemUseContext.Whisper`), which no character sent, and a payload from before it reads as 0. **Whispers (#717):** `/w <player> <message>` (`/whisper`, `WhisperCommand` in `Avalon.World/Chat`, Player access, synchronous) sends the text as typed after the name (trimmed at the ends; the command word and name found as `/p` finds its text, `CommandText`) to one online character, wherever it is on this world server, on `Whisper` with the sender's name; the sender gets an echo on `Whisper` with `SChatMessagePacket.TargetName` (field 7, set only on that echo) naming the recipient as it is spelled. Refusals are system lines to the sender only, nothing sent to anyone else, in this order: no name or no message, "Usage: /w <player> <message>"; the sender's own name (ignoring case), "You can't whisper yourself."; no online character with that name, offline and unknown alike, "No player named <name> is online." (the name as typed). Names are looked up in `OnlineCharacters` (`Avalon.World/Characters`, a World-side singleton, tick thread only): online characters by id and by name in any case, ignoring surrounding spaces (keyed by `CharacterName.LookupKey`, #757), fed from the world's online and offline hooks through `PartyService.CharacterOnline`/`CharacterOffline` (a stale connection's offline changes nothing) and read by the party invite and the whisper alike; `PartyService` takes it as an optional constructor parameter, and `WorldHostGraphShould` pins that production hands both the same instance. **Chat rate limit (#722):** `ChatRateLimiter` (`Avalon.World/Chat`, a DI singleton) gives each sending character one sliding 60 s budget of `Game:ChatMessagesPerMinute` messages (default 10 in `appsettings.json`, not in C#; 0 or below turns it off), shared by plain chat (`ChatMessageHandler`), `/p` (`PartyChatCommand`), `/w` (`WhisperCommand`) and `/ignore` (`IgnoreCommand`, #723, owner decision); no other command counts. Callers ask `Check(characterId, out retryAfter)` first, before any recipient or party lookup (so an over-limit sender learns nothing about who is online), and `Record(characterId)` only once the message is delivered, so a refusal (usage, self-whisper, no such player, not in a party) uses no budget. Over the limit the message is not delivered and the sender gets a system line, "You're sending messages too fast. Try again in {n}s." (n = seconds until the oldest counted message leaves the window, rounded up, at least 1). Timestamps come from the injected `TimeProvider` (a queue per sender, pruned on each call, no timers). Chat runs on the tick, so the service needs no concurrency, but every method takes one short lock because the shutdown despawn can reach `Forget` from another thread. `World.LeaveWorldAsync` calls `Forget(characterId)` (logout, leave to character selection, disconnect), so nothing is held for a character that left. **Ignore list (#723, owner design).** A character ignores other characters of its world by id, online or offline: `CharacterEntity.Ignores`, an `IgnoreList` (`Avalon.World/Social`, World-side, never on `ICharacter`, tick thread only; entries are id, name and when added, oldest first). Memory is authoritative and every check is `Ignoring.Hides(listener, senderId)`, with no database query per message: a whisper to a character ignoring the sender is not sent while the sender still gets its echo and the message counts against the rate limit as delivered; `ChatMessageHandler` and `/p` leave the line out for each listener or member that ignores the sender (the sender's own line always goes out); a party invite from an ignored character is answered `Ok` after every usual refusal, never sent, not answerable (`Respond` finds no invite) and kept by `PartyService` per (inviter, target) until it expires, when the inviter alone gets `InviteExpired` (and `InvitePending` meanwhile for a second invite to that target), or until the target goes offline (the inviter told `InviteExpired`) or the inviter does (ended silently). System lines are never filtered, and whispering a character you ignore is allowed. Commands (`IgnoreCommand`, `UnignoreCommand`, `IgnoreListCommand` in `Avalon.World/Social`, Player access, synchronous): `/ignore <name>` refuses, in order, without exactly one name ("Usage: /ignore <name>"), the caller's own name ("You can't ignore yourself."), a name already on the list ("X is already on your ignore list."), a full list (`Game:MaxIgnoredCharacters`, default 50, range 1-500, "Your ignore list is full (50/50)."), and over the chat rate limit (the limiter's own line; an `/ignore` past the four refusals before it spends one message of the budget whatever the lookup finds, while those four, `/unignore` and `/ignorelist` spend nothing), then finds the character in `OnlineCharacters` or, offline, through `ctx.Then(ICharacterIgnoreRepository.FindCharacterByNameAsync(...))` (by `NameKey`, so in any case; names are unique by key, so at most one character matches, #757), whose callback does nothing if the connection no longer holds that character and otherwise re-checks: no such character ("No character named X exists."), itself by id, already listed by id, full; an accepted one is "You are now ignoring X.", and an invite from that character the caller still holds then ends silently (`PartyService.HideInviteFrom`, owner decision: it becomes a dropped invite, so the caller can no longer accept it and the inviter is told nothing new and sees the usual expiry). `/unignore <name>` (by the name the list shows: "You are no longer ignoring X." or "X is not on your ignore list.") and `/ignorelist` ("Ignoring 2/50: A, B." or "You are not ignoring anyone.") never touch the database. `SMSG_IGNORE_LIST` (`SIgnoreListPacket`, 0x30D0: `Characters`, repeated `IgnoredCharacterDto` `CharacterId`, `Name`) is the whole list: sent by `CharacterSelectHandler` once the list is loaded (one more `Step` after the quest rows, before the pending spawn, empty too), after every change, and by `CharacterDeleteHandler` to each connection holding a loaded list that had the deleted one on it, in the world or selected and waiting to spawn (`IWorldServer.Connections`, `Character` or `PendingSpawn`; taken off in memory there; the rows cascade); a select whose rows were read before the delete committed but applied after keeps the entry until its next select, harmlessly. **Storage:** `CharacterIgnores` (Character DB, migration `AddCharacterIgnores`): `CharacterId`, `IgnoredCharacterId`, `CreatedAt`, key the pair, both foreign keys to `Characters` cascading, an index on `IgnoredCharacterId`. Every change marks `SaveStateTracker.IgnoreChanged(id)`, and the next save carries a `CharacterIgnoreWrite` (built in `CharacterSaveSnapshot`): each marked pair deleted, then inserted again while still on the list, one `INSERT ... SELECT` per entry from the ignored character's row, so a character deleted since it was ignored, or by a delete running alongside the save, skips its row and never fails the save (on Postgres the read takes `FOR KEY SHARE`: a delete committed first is seen, one still running waits for the save and then cascades the row; verified on Postgres 17). Select loads the names the rows hold now (`GetByCharacterIdAsync` joins `Characters`); a rename while the owner is online shows at its next select. `CharacterSelectHandler` takes the repository and `CharacterDeleteHandler` the `IWorldServer` optionally; `WorldHostGraphShould` pins that production hands them over. Command answers, "Unknown command." and every line the server speaks (party joins, leaves, leader and mode changes, leave countdowns, health scaling, quest milestones) are `SChatMessagePacket.System`: channel `System`, sender name "System", account and character 0.
